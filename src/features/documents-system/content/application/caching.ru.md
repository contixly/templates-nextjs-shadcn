# Кеширование

Шаблон использует Next.js Cache Components и теги кеша на уровне репозиториев. Он может работать с
локальным запасным кешем или распределенным кешем на Redis/Valkey.

## Локальное значение по умолчанию

По умолчанию `REMOTE_CACHING_ENABLED=false`. Это упрощает локальную разработку и использует
локальный запасной вариант из пользовательских обработчиков кеша.

## Распределенный кеш

Включайте распределенное хранилище кеша, когда несколько экземпляров приложения должны делить Cache
Components и записи ISR:

| Переменная | Назначение |
| ---------- | ---------- |
| `REMOTE_CACHING_ENABLED` | Включает удаленный режим кеша при значении `true`. |
| `REDIS_URL` или `VALKEY_URL` | URL подключения к сервису кеша. |
| `REDIS_PASSWORD` | Опциональный пароль, если он не включен в URL. |
| `REMOTE_CACHING_PREFIX` | Префикс, который изолирует записи кеша по приложению или окружению. |

Используйте уникальный префикс, если один сервис Redis или Valkey делят несколько окружений.

## Инвалидация кеша функций

Чтение из репозиториев использует теги кеша. Мутации обновляют затронутые теги и пути, чтобы UI
показывал свежие данные рабочих пространств, аккаунтов, команд, приглашений и API-ключей.

## Опциональный пограничный кеш для публичных ответов

Cache Components и обработчики Redis или Valkey кешируют данные приложения и записи ISR. Они не
кешируют полный HTTP-ответ для посетителя. Опциональный пограничный кеш Nginx — отдельный слой
развертывания: он может повторно выдавать полный публичный ответ со страницей документации.

Nginx и Compose необязательны. Локальная разработка и корневой `Dockerfile` работают без них:

```bash
npm run dev
docker build -t nextjs-shadcn .
docker run --rm -p 3000:3000 --env-file .env nextjs-shadcn
```

Передайте те же обычные переменные окружения приложения, которые нужны самостоятельному
развертыванию. Не добавляйте Nginx, Compose, Redis или Valkey только ради локального запуска или
одного контейнера Docker.

Для развертывания в Dokploy, которому нужен общий кеш ответов документации, есть опциональная
топология в `infra/dokploy/compose.yml`. Traefik направляет публичный трафик в Nginx, а Nginx — в
контейнеры Next.js. PostgreSQL и Redis или Valkey остаются внешними по отношению к этому Compose
файлу.

### Что может кешировать пограничный слой

Пограничный слой использует положительный список. Он может кешировать полный HTML только для
`/docs`, опубликованных страниц внутри этого пути и неизменяемых ресурсов в `/_next/static/`. Все
остальные маршруты лишь проксируются и получают `BYPASS`: это главная страница, вход,
защищенные страницы приложения, API, серверные действия, запросы RSC и предварительной загрузки
маршрутизатора, сгенерированные изображения документации и запросы с авторизацией.

Эта узкая граница важна, даже если маршрут выглядит публичным. Пограничный слой не должен сохранять
ответ, который зависит от пользователя, cookie, рабочего пространства или особенностей запроса.

### Проверка развертывания с пограничным кешем

Nginx добавляет к проксируемым ответам `X-Edge-Cache` (`MISS`, `HIT`, `BYPASS` или `EXPIRED`) и
`X-Edge-Replica`. Вызовите `GET /nginx-health`, чтобы проверить процесс Nginx. Вызовите
`GET /api/health` непосредственно в веб-контейнере, чтобы проверить Next.js и его зависимости.

До направления настоящего трафика через пограничный слой запустите проверку с обязательными URL
источника и пограничного слоя, а также с временной cookie авторизованного тестового пользователя,
которую передают через защищенное окружение:

```bash
npm run test:public-cache
```

Проверка сравнивает полные ответы документации для гостя, авторизованного пользователя, разных
cookie и безопасных параметров запроса. Она также проверяет переход каждого пограничного экземпляра
от `MISS` к `HIT` и то, что приватные и служебные запросы остаются `BYPASS`. Не записывайте cookie
и другие учётные данные в документацию, историю команд или отчёты.

### Актуальность и развертывание

HTML документации хранится в пограничном кеше 60 минут. При ошибке источника Nginx не выдаёт
устаревший HTML: истёкшая запись ожидает ответа источника. У каждого пограничного экземпляра свой
временный кеш без общего тома и API для очистки отдельной страницы. При развертывании
принудительно пересоздавайте каждый контейнер пограничного слоя (`force-recreate`): это очищает его
временный кеш и инвалидирует все сохранённые ответы.

Первое развертывание Compose выполняйте вручную. Проверьте оба адреса здоровья, список разрешённых
путей и обходы, а также прогретый `HIT` на каждом экземпляре. Только после этого отдельно решайте,
включать ли автоматическое развертывание.
